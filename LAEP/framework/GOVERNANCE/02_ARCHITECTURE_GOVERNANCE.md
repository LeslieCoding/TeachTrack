# GOVERNANCE/02 — Architecture Governance（架构治理）

负责：模块边界、系统边界、依赖、API、数据流、服务划分、技术债。S3 起
全量启用（见 `SCALE/S3_LARGE.md`），S1/S2 只需要模块划分的基本记录。

## 模块设计

每个模块至少定义：目的、职责、输入、输出、依赖、对外公开接口、内部组件、
数据归属、失败模式、测试策略。禁止模块职责无限膨胀——发现一个模块什么都
管，这本身就是一条要记进 `STATE/TECH_DEBT.md` 的技术债。

## Dependency Graph

S3+ 项目维护模块间依赖关系。改动一个模块前，先搞清楚"谁依赖它"，防止局部
修改在别处炸出回归。S1/S2 可以只在改动前临时搜索一下调用方，不要求正式
维护成文档。

## API Governance

任何公共 API 修改，必须分析：向后兼容性、向前兼容性、消费方（谁在用）、
版本策略、废弃计划、迁移方案。模板见 `TEMPLATES/`（Change Impact 相关）。

## Technical Debt

`STATE/TECH_DEBT.md` 记录：描述、原因、影响、优先级、建议解决版本。禁止
用 TODO 注释掩盖长期结构性问题——TODO 是给下一行代码用的，技术债是给项目
管理用的，两者不能互相替代。
