## 开发顺序

### P1 录题与编辑

目标：教师可以在平板或手机上完整录一道题。

范围：

- 学科、年级、教材版本
- 题型、难度、来源
- 题干、选项、标准答案、解析
- 知识点多选
- 保存草稿、提交审核
- 录入前调用 `/api/v1/questions/duplicates`，重复题干给出提醒
- 编辑时携带 `baseVersion`，409 冲突时提示刷新

验收：

- 在 OPPO Pad 完整录入一道选择题和一道计算题
- 保存草稿后可在列表看到
- 提交审核后可被通过
- 重复题干无法静默保存
- 两处同时修改同一道题时，后提交方收到版本冲突

### P2 批量导入

目标：一次导入几十到几百道题。

推荐格式顺序：

1. 粘贴文本：按空行或题号切分，先预览再入库
2. DOCX：提取题干、选项、答案、解析
3. CSV：教师可控字段映射
4. 试卷分析结果直接批量入库

每条预览记录必须显示：

- 切分后的题干
- 识别出的题型和难度
- 匹配到的知识点
- 重复检测结果
- 错误原因

验收：

- 一次导入 50 道题
- 重复执行同一批导入不产生重复题
- 无法识别的条目进入错误列表，不静默丢弃
- 导入后可批量审核

### P3 题库管理

范围：

- 学科、年级、题型、难度、审核状态、知识点筛选
- 批量审核、批量软删除、恢复
- 题目总数、待审核数、各知识点题量
- 最近修改与版本历史

验收：

- 从 500 道题中筛出“初三 + 电功率 + 难度 3 + 待审核”
- 批量通过 20 道题
- 软删除后列表隐藏，数据仍可恢复

### P4 图片与扫描件

App 相册上传、题图显示以及 PDF/DOCX 导出嵌图的界面代码保留；原 Cloudflare KV 已删除，Java 资产接口和本机文件存储已启用。

待补：

- 真机验证 Java 题图文件存储与签名访问
- 拍照与裁剪旋转
- 区分题干图、选项图、解析图及精确插入位置
- 原试卷 PDF 与页面截图关联

图片作为文件保存，不直接塞进 PostgreSQL。

### P5 AI 生成与变式

前置条件：题库已有至少 300 道教师审核题，避免 AI 从空库生成噪声。

范围：

- Provider 抽象：OpenAI / Kimi / Claude / 本地模型
- 变式题优先基于历史错题
- AI 原创必须进入 `NEEDS_TEACHER_REVIEW`
- 自动检查题干完整性、答案唯一性、单位、难度、知识点匹配
- 与已有题做三级去重
- 教师确认后才能进入 `APPROVED`

验收：

- 生成 10 道变式题，至少 8 道通过教师审核
- 重复题不会进入题库
- AI 写操作全部有审计记录
